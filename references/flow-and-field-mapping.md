# 字段映射

源数据是千牛“通用模板”，输出是用户税局模板。负总金额发票整票排除，基本信息和明细两个 sheet 都不写。所有流水号、订单号、税号、账号按文本保留。输出按模板约定使用文本值，零税率写 0，其余空值写真正空白。

V260401 原始模板“2-发票明细信息”A1 明确要求“全部数据使用文本输入”，税率列说明要求“以小数形式填写，如‘0.13’代表税率13%”。因此税率也遵循文本输入契约：零税率在最终 XLSX 中必须有实际文本值 `0`，不能留空；不要为符合一般分析表的数值类型惯例改成数值单元格。计划校验和最终文件回读都必须保留零值。

新作业的输出流水号来源为 `order_no`：在最终生成税局工作簿时，按内部申请流水号读取本次入选原件行的“订单编号”，去除首尾空白后作为文本写入。每个可导出申请的所有源行均须有文本订单编号且一致，长度不超过20位；同一工作簿内不同可导出申请的订单编号不能重复。缺失、非文本、多订单、超长或同次重号会使本次模板生成失败并保留原件、计划及异常清单，不截断、拼接、合并申请或静默退回申请号。暂缓、负数排除、未入选及已取消申请不占用输出编号；不新增跨批次订单去重，也不据历史同订单记录丢弃取消后提交的新申请。

内部计划及明细的 `invoice_serial_no` 继续保存平台申请号，选择、同意、商品匹配、异常清单、计划指纹与恢复身份不变。生成报告的 `invoice_serial_mapping` 记录内部申请号到最终输出流水号的映射。新单店、新批次及新离线重放冻结 `export_serial_source="order_no"`；恢复沿用冻结值，旧作业/旧批次缺字段时按 `application_no` 保持原输出，包括旧批次尚未启动的店铺。已完成文件不回写；编号校验不介入 `--plan-only` 的商品补证流程。

## 基本信息

| 目标字段 | 来源及规则 |
| --- | --- |
| 发票流水号 | 新作业取该申请唯一的通用模板订单编号文本；每票一行，旧作业恢复按冻结规则 |
| 发票类型 | 普通发票、增值税普通发票、增值税纸质普通发票、增值税电子普通发票、全电/数电普通发票→普通发票；增值税/全电/数电专用发票→增值税专用发票 |
| 特定业务类型 | 留空 |
| 是否含税 | 是 |
| 受票方自然人标识 | 企业/公司/个体工商户→否；个人/自然人→是 |
| 购买方名称 | 发票抬头 |
| 购买方纳税人识别号 | 购方税号；企业必填 |
| 购买方地址 | 企业地址 |
| 购买方电话 | 企业电话 |
| 购买方开户银行 | 开户行 |
| 购买方银行账号 | 开户账号 |
| 是否展示购买方地址电话银行账号 | 始终留空，不复制来源值或自动生成 |
| 备注 | 发票备注 |
| 其他列 | 留空 |

同一申请的基本字段取非空一致值，有两个非空冲突值就整票暂缓。展示选项不参与源值一致性检查，因为用户已约定不填写。

按已确认业务规则，千牛标记“增值税纸质普通发票”的申请按数电普通发票生成，税局模板字段填写“普通发票”。通用模板原件和规范化输入的源行保留原票种，只有输出基本信息采用映射值；不会改动模板本身“仅支持数电发票”的说明。此映射不豁免商品、购方、金额、税率或负数排除规则，也不扩展到未列出的票种。

## 明细信息

| 目标字段 | 来源及规则 |
| --- | --- |
| 发票流水号 | 每条明细重复对应基本信息表的输出流水号，不去重、不留空 |
| 项目名称 | 票聚 invoice_name |
| 商品和服务税收编码 | 票聚 tax_code |
| 规格型号 | 票聚 properties_value（颜色及规格）；空则空，不取 invoice_spec |
| 单位 | 票聚 issuing_office |
| 数量 | 通用模板正商品源行数量 |
| 单价 | 留空 |
| 金额 | 通用模板正商品金额＋唯一归属的价外费用 |
| 税率 | 按冻结的店铺配置：piaoju 取票聚明确税率，fixed 取配置 rate；写小数文本如 0.01（1%），零税率写文本 0，单元格不得为空 |
| 折扣金额 | 紧随正商品的负金额折扣源行；无折扣留空 |
| 优惠政策等其他列 | 留空 |

订单商品编码是源行到票聚的关联键，不写入无对应字段的输出列。订单详情金额只帮助判断源行属于哪个编码，与价外费用合并前的原商品金额比较，不覆盖源金额、折扣和数量。original_amount、extra_fee_amount、extra_fee_source_rows 保留费用合并证据，不新增工作簿列。computed_unit_price 是计划内复核值，不写单价。

千牛 SKU/详情规格仅作订单关联证据：完整且名称唯一的属性名值可忽略展示顺序比较，名称或值不一致仍阻断；不重排未命名或歧义文本，不改写原证据。该比较不影响上表“规格型号”仍取票聚 `properties_value`。

同申请同订单的完整同价、同量、同折扣商品组，可按[整组等价证明](detailed-rules.md#2-商品行匹配)核验。只有全部一对一分配得到相同业务明细集合时，才以稳定子订单顺序生成；源行与具体口味的原始对应关系仍标为组级等价，不声称逐行唯一。每个商品仍独立写一条明细，规格取该编码的票聚 `properties_value`，数量、正金额、折扣保持源值，不合并商品、不新增工作簿字段。组级证据仅保留在本地输入和计划，独立复核重算组覆盖及分配。

税率配置见[按店铺配置税率](tax-rates.md)。固定税率不改写源含税金额，也不以票聚缺少税率为由暂缓；票聚名称、税收编码、单位及开票启用状态等仍需通过核验。

## 第三、四表

3-特定业务信息、4-附加要素信息始终保留表头并清空数据区。隐藏辅助页完整保留，不算新增业务表，不填数据。

模板处理按工作表名称和表头定位，不依赖 sheet1.xml/sheet6.xml 或固定列位置。缺少必需表头、重复必需表头或可见业务表结构不符时停止，不能猜测列含义。
