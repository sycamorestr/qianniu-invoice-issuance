# 完整业务规则

## 1. 日期、申请集合与主体

输入范围按申请日期计算，不是订单付款日期。新任务显式选择 `--date` 单日或 `--all-pending` 最近两个日历月；后者以创建时的北京时间今日为结束日期，向前两个日历月为开始日期，首尾包含，例如 2026-07-28 至 2026-09-28。申请列表与通用模板导出使用同一冻结起止日期，按该范围完整导出；恢复沿用原范围，不移动窗口或扩为全历史。

新任务还固定 `query_scope.countdown="started"`，仅选择页面“开票倒计时＝已开始”（接口 `rightsRemainTime=100`），不包含“已超时”或“未开始”。导出接口会忽略倒计时筛选，所以完整原件“待处理”集合必须再与完整筛后申请列表流水号取交集。禁止用 `remainTime>0` 等未证明口径替代平台筛选。旧任务没有 countdown 字段时沿用原选择规则，不静默升级；新筛选须新建任务。

日常执行默认复用已运行的专用浏览器；确认环境未运行时，按现有持久化 `user_data_dir`、Profile 和固定非零端口正常启动 Edge 一次，读取原目录保存的会话，`--connect-only` 可禁止启动进程。作业复用已有业务页，缺少固定 role 时按业务 URL 自动补齐一次，不要求用户手动开页；工作台的主页配置由技能在内存中补入业务角色，原配置与主页保持不变。进程归属、端口或目录锁冲突不能通过换环境或循环启动绕过。登录跳转、验证码、主体不符或补页失败立即停止，不循环恢复。采集阶段已登记页面关闭或失效时，先找回同一 context 中已有页面，找不到返回 `page_missing` 并停止，不反复新建替代页。核对千牛店铺和票聚开票主体，写入 capture_context.json；coid、uid、agentId 来自本次已核对页面。页面存在及 URL 没有 login 字样不等于已登录，缺少正向主体证据时停止并申请人工介入。历史数据离线重放必须显式 --replay，不把历史核对时间改成当前时间。

千牛身份核验支持已确认的完整子账号：清单 `login_username` 或单店 `--expected-account` 有值时，必须与当前页面 `context.realNick` 精确匹配，允许 `store` 保留工作台显示别名；没有账号约束时仍按原 `store` 精确核验。账号不是密码，也不能填普通备注、截断子账号或猜测别名。保留接口原始店铺昵称 `observed_store` 与账号 `account_nick`，恢复时固定原观察值及账号约束，不能借别名变化切换实际店铺；票聚主体及 agentId/coid/uid 的核对规则不变。

申请列表用于完整性、订单关联及倒计时资格核对。服务端 `total` 可能是待处理计数，而分页数据仍可能夹带其他状态；分页总数必须稳定，流水号不能冲突或漏页。`applyStatus`（包括值为 `1`）只记录列表快照，不能替代通用模板状态。applications.json 的 rows 保留本次筛选下全部观察到的申请，list_non_pending_snapshot_rows 是其中非待处理状态的重叠诊断子集；api_total 是服务端 total，total/observed_total 是实际观察到的唯一流水号数。旧检查点的 excluded_non_pending_rows 仅作兼容读取，不再生成。

下载的通用模板是状态、数量和金额依据，必须具有“开票状态”或“申请状态”列，缺列是输入错误。每个源行优先读取“开票状态”，其值为空时才读取“申请状态”；仅值准确为“待处理”的源行有资格进入生成。started模式再与完整筛后快照的 serialNo 集合取交集，缺快照、计数不完整、范围不符或哈希变化即停止。selected_application_ids 按入选源行原序去重；非待处理行进入 ignored_template_rows，倒计时未入选的待处理行单独记录 filtered_out_countdown_rows，均不查订单、不进入税局模板。

collection_files.py orders 写入 selection.json，绑定通用模板 SHA-256、源行数、状态分布、待处理源行数、流水号顺序和忽略状态；started模式额外保存 query_scope、applications_sha256、raw_pending_source_row_count、raw_pending_application_ids、filtered_out_countdown_application_ids 和 filtered_out_countdown_rows。倒计时未入选申请不计入 ready/blocked/excluded。订单、商品编码和票聚汇总检查点继承选择哈希；下游重新核对原件与筛选证据。原始通用模板始终字节不变，可能包含未入选申请。

## 2. 商品行匹配

商品关联粒度为“申请流水号＋源行号→订单明细→完整商品编码”。同一个订单可以多个商品编码；同一编码也可能多个子订单，不能只按编码去重。

依次使用直接商品编码/子订单标识、商品标题、规格、数量和已证实同口径金额筛选。已有源编码仍需核对订单明细，不能绕过矛盾检查。HTML 实体和无意义空白可归一，不能模糊猜测。两个都有值的字段相冲突时剔除候选，零候选或多个候选整票暂缓。同一申请不能重复消费同一订单明细。没有子订单号的历史详情保留本次明细证据编号。

标题、规格或数量不足以唯一对应时，必须补读订单详情/优惠明细并重跑匹配，不能仅凭批量列表歧义就结束核对。金额证据必须指向具体订单明细，保留来源页面或字段、原值/计算关系和优惠口径。只有与通用模板正金额同口径的值才能标记 order_detail_gross / promotion_detail_gross。折后金额需先解释折扣并还原到相同口径，不能直接贴上述标签。通用接口 priceInfo.realTotal 不自动作为该证据。详情补查后仍歧义或页面不可读取，才说明具体原因并暂缓。

订单批量搜索每批最多 50 个编号，取完返回分页。记录并核对查询范围；近三个月未返回不等于已证实为历史订单。有已验证历史范围参数时先批量补查，没有时仅对缺失项读详情并说明原因，不猜查询参数。批查中商家编码为空的明细必须保留，并将对应订单补查详情一次；不能在合并时使整店失败，也不能丢掉空码明细后把其他商品判为唯一匹配。详情已核对主/子单、标题和数量但仍无商家编码时，涉及该订单的申请整票暂缓，其他完整订单继续生成。真正未命中也逐票暂缓；未加载、登录失效或响应损坏不等于商品缺码。赠品、退款、拆单或数量关系无法解释时不猜配。保留每批查询条件和返回订单编号。

old_details.json 与 supplemental_details.json 都必须被消费。按可靠订单号和子订单号合并，重复同值可复用，非空字段冲突不能覆盖。自动生成金额证据时核对详情原始 price_cell、单价×数量、标题与数量、通用模板合并费用前的正商品金额及唯一关联；不以金额恰好相等作为唯一依据。推导结果和失败原因写入本次生成目录，不修改原始文件，仍有歧义继续暂缓。

## 3. 票聚查询与字段

商品类型和商品状态均不选。请求 data 省略 sku_type、enabled；返回 enabled 可作为证据，但不据此排除商品。invoice_enabled 是独立字段，必须明确为真。

每个去重编码使用 @@完整编码查询，返回 sku_id 必须完全相同且唯一；千牛/票聚仅出现半角与全角括号差异时，允许将 `(`/`（`、`)`/`）` 归一后唯一匹配，保留接口返回的原始 sku_id 和 match_basis 证据。归一后多个候选仍阻断。不能把其他名称相似项当别名。invoice_name、tax_code、issuing_office 必须有值。properties_value 允许为空；明确存在的原始空值不能被其他别名回填。invoice_spec 永远不作规格来源。

税率规则：
- 接口 tax_rate 有值时必须为 0 到 1 的有限小数；虚拟分类不猜测覆盖。
- 缺 tax_rate 时，虚拟分类仅接受明确百分比文本，如 13% 或 13%税率，或“零税率”。裸数字和含多个数字的分类名称无效。
- 明确零税率或显式 0：税率写入 0，不能留空；内部 tax_rate_effective=0 保留用于冲突检查。不要求补 tax_rate_zero。
- “零税率”分类与显式非零税率矛盾时暂缓。通用模板正行或折扣行有明确税率时必须与有效税率一致。
- 缺值、未知值不自动当作零税率。

网络、登录和响应格式失败不等于商品不存在。先补查失败项；确认不限类型/状态仍未精确命中才报告未匹配。

## 4. 金额与明细

按原始源行顺序、申请流水号分组：
- 除价外费用外，每个正商品金额源行生成独立商品明细，数量必须为正的有限数。
- 普通正额申请中，紧随正金额的负行成为该明细折扣；不另起商品、不合并商品行。
- 负数发票：开票总金额为一致、有限的负数时，状态为 excluded_negative，整票不开具，不生成商品明细，不写 1-发票基本信息和 2-发票明细信息。无需为该票继续做商品金额或数量匹配；原件及排除记录保留，不能改成正金额。总金额冲突或无效仍报数据异常，不能任选负值排除。
- 正额申请中的孤立负行、连续负折扣、折扣大于前一正金额、折扣订单不一致、零商品金额、非有限数均为异常；负折扣不是负数发票，不因此排除整票。
- 每张可输出发票的商品金额与折扣之和按分币等于开票总金额；最终复核同时检查源行和原值，并确认负总金额发票没有进入输出。
- 单价留空；无折扣留空。订单、票聚金额不得覆盖源表金额。
- 货物名称准确为“价外费用”的正金额累加到同申请、同订单唯一正商品源行的金额，不另起明细、不增加数量、不改变商品原折扣；合并后的金额沿用该商品票聚字段和税率。多个费用行可累加，每行只使用一次。
- 费用不作为商品编码查询对象；费用金额非正数/无效、订单号缺失、同订单没有或存在多个正商品源行、费用明确税率/编码/子订单号与归属商品冲突，均整票暂缓。没有归属证据时不按行序、最大金额或跨税率分摊。
- detail_lines 保留 original_amount、extra_fee_amount、extra_fee_source_rows，amount=原商品金额+费用合计。订单金额匹配使用 original_amount；折扣仍须直接相邻于原正商品行，费用行不充当折扣归属商品。独立复核必须核对所有费用源行恰好使用一次。

详细目标字段以 flow-and-field-mapping.md 为唯一映射说明。

## 5. 阻断级别与输出

整次阻断：主体/日期不符、申请分页或导出不完整、重复源行、已选申请缺失、订单分页响应不完整、票聚请求未完成、模板结构异常或最终复核失败。不能只挑剩余票后宣称整次成功。

逐票暂缓：明确订单未命中、补查后商品关联仍不唯一、字段冲突、票聚明确未命中/多匹配/不开票/缺字段、金额不平、税率冲突、价外费用无法确定归属。每张暂缓票必须出现在 exceptions.csv 中；输出不含该票任何基本或明细行。

完整申请数=通过数+暂缓数+排除数。负数发票记为排除，不计入可开数量和金额；exceptions.csv 保留“负数发票按规则不开具”及原负总金额，run.json 分别记录 excluded_count、excluded_amount。金额汇总使用申请总金额，不用残缺明细合计冒充暂缓金额。暂缓票缺少有效总金额时，暂缓合计标记为未知（null），不填零。没有申请正常返回 no_applications；全部排除返回 all_excluded；没有通过且存在暂缓票返回 all_blocked，均不制造可导入业务数据。

终态交付规则：complete 交付原始通用模板副本、税局模板、异常清单和 run.json；no_applications、all_excluded 与 all_blocked 不交付可导入税局模板，但仍交付已取得的原始通用模板副本、异常清单和 run.json。仅当列表明确为空且实际导出 HTTP 成功、响应为零字节时，no_applications 没有原件可交付，改为保留查询快照、空响应 common-export.bin、异常表头和报告，不制造 XLSX；列表为零但导出非空时保留原件，并按冻结筛选确定交集，完整判定见[输入输出](input-output-contract.md#原始检查点)。failed 保留失败 run.json、已取得的原始通用模板与检查点，不能把未完成文件称作税局模板。导出前失败时没有原件可交付。

生成前检查全局错误。写入临时文件，独立复核成功后才命名为最终 XLSX。独立复核覆盖源正行、订单关联、数量、金额、折扣、票聚字段、税率、基本信息、四表结构及原模板部件。run.json 保存输入哈希和结果状态。

## 6. 恢复与重放

每批查询形成单独文件。中断后复用本次已成功且输入相同的批次，只补查失败项；selection.json 或通用模板哈希不一致时开启新目录。更换日期、主体、查询条件时也开启新目录。登录失效、验证码或权限变化先解决会话问题，不能反复盲重试。

本地生成总使用新输出目录，失败保留 run.json 和已完成阶段供诊断。规则修改后可以用 --replay 对历史原始快照重新生成，不重新访问网站，不覆盖原交付文件。重放仍须重新运行校验，不复制旧 verification.json 充当本次结果。
