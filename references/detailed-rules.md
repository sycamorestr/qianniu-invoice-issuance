# 完整业务规则

## 1. 日期、申请集合与主体

输入是申请日期，不是订单付款日期。单日导出与申请列表使用同一日期；长区间拆成平台允许的窗口，分别完成采集和范围核对。当前脚本的标准运行单元是一天。

页面未打开但登录有效时，按记录 URL 打开。核对千牛店铺和票聚开票主体，写入 capture_context.json；coid、uid、agentId 来自本次已核对页面。历史数据离线重放必须显式 --replay，不把历史核对时间改成当前时间。

完整待处理列表以 serialNo 固化 selected_application_ids。分页总数必须一致，不能重复或漏页。实时列表 applyStatus 必须为已验证的 1；导出申请状态必须为“待处理”。未知状态不能视为待处理。导出与列表变化时重新采集对应阶段，不能用两份不一致快照拼成成功结果。

通用模板必须包含每张已选申请。额外未选申请不进入输出。申请列表与源表订单号必须一致。原始通用模板保留，记录文件哈希、申请列表采集时间和主体核对记录。

## 2. 商品行匹配

商品关联粒度为“申请流水号＋源行号→订单明细→完整商品编码”。同一个订单可以多个商品编码；同一编码也可能多个子订单，不能只按编码去重。

依次使用直接商品编码/子订单标识、商品标题、规格、数量和已证实同口径金额筛选。已有源编码仍需核对订单明细，不能绕过矛盾检查。HTML 实体和无意义空白可归一，不能模糊猜测。两个都有值的字段相冲突时剔除候选，零候选或多个候选整票暂缓。同一申请不能重复消费同一订单明细。没有子订单号的历史详情保留本次明细证据编号。

标题、规格或数量不足以唯一对应时，补读订单详情/优惠明细。金额证据必须指向具体订单明细，保留来源页面或字段、原值/计算关系和优惠口径。只有与通用模板正金额同口径的值才能标记 order_detail_gross / promotion_detail_gross。折后金额需先解释折扣并还原到相同口径，不能直接贴上述标签。通用接口 priceInfo.realTotal 不自动作为该证据。

订单批量搜索每批最多 50 个编号，取完返回分页。近三个月未命中时查询历史页或逐单详情；真正未命中或缺商家编码则该票暂缓。赠品、退款、拆单或数量关系无法解释时不猜配。保留每批查询条件和返回订单编号。

## 3. 票聚查询与字段

商品类型和商品状态均不选。请求 data 省略 sku_type、enabled；返回 enabled 可作为证据，但不据此排除商品。invoice_enabled 是独立字段，必须明确为真。

每个去重编码使用 @@完整编码查询，返回 sku_id 必须完全相同且唯一。模糊匹配和多个精确结果都不能自动选一个。invoice_name、tax_code、issuing_office 必须有值。properties_value 允许为空；明确存在的原始空值不能被其他别名回填。invoice_spec 永远不作规格来源。

税率规则：
- 接口 tax_rate 有值时必须为 0 到 1 的有限小数；虚拟分类不猜测覆盖。
- 缺 tax_rate 时，虚拟分类仅接受明确百分比文本，如 13% 或 13%税率，或“零税率”。裸数字和含多个数字的分类名称无效。
- 明确零税率或显式 0：输出空白，内部 tax_rate_effective=0 保留用于冲突检查。不要求补 tax_rate_zero。
- “零税率”分类与显式非零税率矛盾时暂缓。通用模板正行或折扣行有明确税率时必须与有效税率一致。
- 缺值、未知值不自动当作零税率。

网络、登录和响应格式失败不等于商品不存在。先补查失败项；确认不限类型/状态仍未精确命中才报告未匹配。

## 4. 金额与明细

按原始源行顺序、申请流水号分组：
- 正金额生成独立商品明细，数量必须为正的有限数。
- 紧随正金额的负行成为该明细折扣；不另起商品、不合并商品行。
- 首行负数、连续负数、折扣大于前一正金额、折扣订单不一致、零商品金额、非有限数均为异常。
- 每票正金额与折扣之和按分币等于开票总金额；最终复核同时检查源行和各项原值。
- 单价留空；无折扣留空。订单、票聚金额不得覆盖源表金额。
- 价外费用暂不建立税收分类或商品映射，不并入其他商品，整票暂缓。

详细目标字段以 flow-and-field-mapping.md 为唯一映射说明。

## 5. 阻断级别与输出

整次阻断：主体/日期不符、申请分页或导出不完整、重复源行、已选申请缺失、订单分页响应不完整、票聚请求未完成、模板结构异常或最终复核失败。不能只挑剩余票后宣称整次成功。

逐票暂缓：明确订单未命中、商品关联不唯一、字段冲突、票聚明确未命中/多匹配/不开票/缺字段、金额不平、税率冲突、价外费用。每张暂缓票必须出现在 exceptions.csv 中；输出不含该票任何基本或明细行。

完整申请数=通过数+暂缓数。金额汇总分别使用申请总金额，不用残缺明细合计冒充暂缓金额。暂缓票缺少有效总金额时，暂缓合计标记为未知（null），不填零。没有申请正常返回 no_applications；全部暂缓返回 all_blocked，保留异常清单，不制造可导入业务数据。

生成前检查全局错误。写入临时文件，独立复核成功后才命名为最终 XLSX。独立复核覆盖源正行、订单关联、数量、金额、折扣、票聚字段、税率、基本信息、四表结构及原模板部件。run.json 保存输入哈希和结果状态。

## 6. 恢复与重放

每批查询形成单独文件。中断后复用本次已成功且输入相同的批次，只补查失败项；更换日期、主体、查询条件时开启新目录。登录失效、验证码或权限变化先解决会话问题，不能反复盲重试。

本地生成总使用新输出目录，失败保留 run.json 和已完成阶段供诊断。规则修改后可以用 --replay 对历史原始快照重新生成，不重新访问网站，不覆盖原交付文件。重放仍须重新运行校验，不复制旧 verification.json 充当本次结果。
